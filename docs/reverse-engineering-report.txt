getAXState 역공학 조사 결과 — 2026-10-15

결론
브라우저용 getAXState의 실용적인 동등 기능은 자체 구현할 수 있다. 브라우저 수집·정규화·iframe 병합·요소 액션 매핑은 설치된 JavaScript에서 직접 확인했다. 출력 렌더링과 revision 관리는 Swift 계열 WebAssembly 모듈에 있으며, 앱을 실행하지 않고 독립 호출하는 데 성공했다.
다만 원본 WASM으로 동일 출력을 얻는 것과, 해당 알고리즘을 모두 자체 코드로 복원하는 것은 다르다. 이번 결과는 원본 모듈의 독립 실행·관찰 및 JavaScript 분석이며, 모든 사이트에서 글자 단위로 일치하는 자체 구현을 완성한 결과가 아니다.

1. 대상과 사용 도구
- GitHub: https://github.com/morluto/rea — Reverse Engineer Anything.
- npm REA 6.5.0. 참고 소스 체크아웃 d69acc3455c33f90a2fc4381db43d38b6af50622.
- Node 22.21.1, 공식 WebAssembly/wabt 릴리스 1.0.42 macOS arm64. WABT 다운로드 SHA-256을 공식 checksum 파일과 비교했다.
- 실제 분석 대상: /Applications/ChatGPT.app, 26.928.21956, browser 플러그인의 scripts/browser-service.mjs 및 browser-accessibility.wasm.br.
- /Applications/Codex.app의 오래된 별도 설치본은 26.721.81911이었다. 이번 분석은 기존 대화에서 getAXState를 제공한 ChatGPT.app 내 Codex/브라우저 런타임을 대상으로 한다. 모든 Codex 배포판이 동일하다고 일반화하지 않는다.
- 실시간 GitHub 순위 1위 여부는 본 분석의 검증 항목이 아니다. 사용자가 지칭한 REA 저장소는 찾았다.
- 앱/확장 설치나 MCP 전역 설정은 바꾸지 않았다. REA는 프로젝트 내 로컬 npm 디렉터리에 설치해 CLI로 사용했다.

2. 실제 실행 흐름
getAXState(options)
 → tab.ax.get("state", {disableDiffing})
 → tab_ax_get_state 명령 핸들러
 → 탭별 세션 확인, 페이지 이동·paint·AX 변경 안정화 대기
 → Page.getFrameTree + DOMSnapshot.captureSnapshot
 → frame/target별 Accessibility.getFullAXTree
 → DOM 메타데이터와 AX 노드 결합 및 정규화
 → iframe 트리 병합, 민감 입력·closed shadow 관련 필터링
 → {capturedAt, tab, nodes, warnings} JSON
 → WebAssembly buildRevision(previousRevision, snapshot, mode)
 → 렌더링 텍스트 + 요소 번호 ↔ 내부 identity 조회
 → Browser tab / Title / URL 헤더 추가
 → getAXState가 결과 텍스트를 emit하고 같은 문자열을 반환

getAXState 자체는 HTML 파서가 아니다. 기본 의미 트리는 Chromium의 Accessibility 도메인에서 받는다. DOMSnapshot은 bounds, input 특성, identifier, closed shadow 같은 보조 정보를 붙이는 데 사용한다. 전체 HTML 문자열을 먼저 모델에게 보낼 필요는 없다.
DOM-only 탭처럼 tab.ax가 없는 경우에는 별도로 playwright.domSnapshot()으로 fallback하는 경로도 래퍼에서 확인했다. 따라서 모든 환경에서 getAXState라는 이름이 같은 실제 AX 구현을 뜻하는 것은 아니다.

3. JavaScript에서 직접 확인한 구현
A. AX 수집
Accessibility.enable을 target별로 한 번 활성화하고, Accessibility.getFullAXTree({frameId})를 호출한다. computedStyles:[], includePaintOrder:false, includeDOMRects:false인 DOMSnapshot.captureSnapshot도 호출한다. 이 옵션이어도 실제 코드에서 snapshot.layout.bounds를 읽는다.

B. 트리 정리
ignored 노드를 제외하면서 자식 노드를 보이는 부모로 연결한다. AX properties는 허용 목록을 거쳐 직렬화한다. nameSource, relatedNodes, parentIndex를 남긴다. iframe은 DOM.getFrameOwner로 부모 소유 요소를 찾고 frame 깊이 순서대로 합친다. 다른 target의 iframe도 별도 debugger 연결로 수집하는 코드가 있다. 수집 실패한 iframe은 warnings에 기록된다.

C. 입력·shadow 처리
input의 type/autocomplete/id/name/placeholder/aria-label/title 등을 보고 username/email/OTP/password/phone 계열을 식별한다. 해당 값 또는 관련 하위 노드의 이름·설명 등이 제거되거나 <redacted>로 치환된다. closed shadow 내부와 관련 참조를 처리하는 분기도 있다. 이를 무시하고 단순 AX 덤프만 만들면 원본과 다른 내용이 출력될 수 있다. 모든 비밀을 완벽하게 탐지한다는 보장을 의미하지는 않는다.

D. 요소 identity
관찰된 identity 구성은 다음과 같다.
  [String(tabId), targetID ?? "", String(backendDOMNodeID) 또는 nodeID]
각 문자열을 UTF-8 바이트 길이:내용으로 인코딩하고 |로 연결한다.
예: 탭1, target 빈문자열, backendDOMNodeID2 → 1:1|0:|1:2
이는 모델에게 보이는 작은 정수 element_index와 다르다. WASM이 정수와 identity 사이의 revision별 매핑을 관리한다.

E. 액션 연결
element_index → revision.identityForElement(index) → targets Map → target / backendNodeId / frameId / loaderId.
내부 대상이 없으면 stale or missing 오류를 낸다. 현재 mainFrameId:loaderId와 캡처의 documentKey가 다르면 previous page 오류를 낸다. 동일 session·document에 속한 캡처인지 확인하는 provenance 검사도 있다. 원본에 가깝게 만들려면 번호 출력뿐 아니라 이 매핑과 유효성 검사도 필요하다.

F. 안정화 대기
코드에서 확인한 값: navigation 확인 대기 최대 약5초, first paint 대기 최대 약5초, AX quiet 루프 최대750ms, navigation 후 quiet 기준50ms / 그 외100ms, poll25ms. 페이지가 비었거나 이동 중이면 재캡처하는 분기가 있으며, 모든 호출이 항상 이 최대시간을 기다리는 것은 아니다.

4. WASM에서 확인한 경계
원본 .wasm.br: 4,084,148바이트.
압축 해제 .wasm: 20,208,690바이트.
함수 정의 80,910개, 함수 import34개, export11개. 숫자 대부분에는 Swift/Foundation/ICU 등의 런타임이 포함되어 있으므로 8만 개가 모두 AX 알고리즘이라는 뜻은 아니다.
.swift1_autolink_entries, Swift 런타임 문자열, BrowserAccessibilityRevision, UIElementRenderTree, NextAvailableElementIDIterator 같은 타입 메타데이터가 있다. Swift 계열 컴파일 결과라는 근거다.
name, producers, sourceMappingURL, .debug_info, .debug_str 섹션은 없었다. 원래 Swift 파일·변수 이름과 원본 소스 전체를 복원했다는 주장은 할 수 없다.

주요 export:
- computer_use_browser_wasm_allocate / deallocate
- computer_use_browser_wasm_revision_create
- computer_use_browser_wasm_revision_release
- computer_use_browser_wasm_revision_text_length / copy_text
- computer_use_browser_wasm_revision_identity_length / copy_identity
- computer_use_browser_wasm_revision_is_value_settable

앱의 JS 호출 순서와 동일하게 UTF-8 JSON을 WASM 메모리에 복사하고 revision_create에 이전 포인터, JSON 포인터·길이, full 플래그, 결과포인터 주소를 전달했다. 반환 revision에서 text와 identity를 읽었다.
core-probe.mjs는 이 ABI를 사용한 별도 작성 하네스다. 앱을 열거나 브라우저에 연결하지 않고 작동하며, Node WASI env는 명시적으로 전달한 값만 받고 preopens는 비어 있다.

5. 독립 실행으로 관찰한 동작
5-1. 출력과 들여쓰기
입력에는 parentIndex와 role 등이 들어간다. 출력에는 실제 탭 문자로 계층 들여쓰기가 들어간다.
  0 AXWebArea Description: AX test, URL: example.com/test
	1 button A
	2 button B
role은 단순 원문이 아니라 변환된다. RootWebArea→AXWebArea, generic→container, StaticText→text, combobox→combo box 등의 사례를 확인했다.

5-2. 번호 유지와 재할당
기본 순서 A=1, B=2일 때:
- A 이름 변경 → A의1 유지.
- 앞에 새 요소 삽입 → 새 요소에 다음 번호, 기존1·2 유지.
- 동일한 라벨이어도 backendDOMNodeID 교체 → 새 번호.
- B,A 순서로 재배열 → B는2 유지, A는새 번호인 사례.
따라서 backendDOMNodeID만 같으면 표시번호가 영원히 고정된다는 설명은 정확하지 않다. 렌더 트리의 순서·revision matching도 관여한다. 정확한 내부 matching 알고리즘 전체는 미복원이다.

5-3. 변경분
작은 트리는 바뀌지 않아도 전체 텍스트를 다시 반환한 사례가 있다. 큰 트리는 다음 문자열을 반환했다.
  There has been no change in the accessibility tree.
바뀐 경우 실제 출력:
  The following is a diff from the previous accessibility tree with ~ and + representing changed and added elements, respectively. Removed elements are summarized by ID range.
  Removed element IDs: 4-5
  ~	2 button Renamed action
  +	101 button Added
위 줄의 	는 설명을 위한 표기이며 JSON 결과에는 실제 탭 문자가 저장되어 있다.

5-4. 변경분 선택 기본 설정
WAT의 초기화 코드에서 확인:
  TINYSKY_AX_TREE_DIFF_MIN_SAVED_BYTES → 기본1000
  TINYSKY_AX_TREE_DIFF_MIN_SAVED_RATIO → 기본0.3
후자는 i64 비트패턴4599075939470750515를 double로 해석하면0.3이다.
독립 실험에서는 unchanged 축약 결과가51바이트일 때 full1050바이트면 전체, full1051바이트면 unchanged 결과로 전환했다. 절약량999/1000바이트 경계다.
비율 환경변수를0.1/0.2/0.25/0.3/0.5로 바꿨을 때 큰 트리에서 diff/full 선택이 달라졌다. 기본 설정 결과는 측정한 구간에서0.3 설정과 같았다. 세부 비용 산정과 모든 예외를 포함한 완전한 분기 복원은 아니다.
disableDiffing:true는 전체 렌더링을 강제하지만 기존 표시번호를 전부 새로 매기지는 않았다.

5-5. URL 축약
확인한 출력 단계:
- https://www. 제거 후 host/path/query/fragment 표시
- fragment 또는 query를 생략한 표시
- example.com/long/pa… 같은 축약
- …만 남김
서로 다른 URL300개와 동일 URL300개 반복의 출력이 달랐다. 동일 URL을 반복하면 긴 쿼리까지 남는 경우가 있었다. 따라서 매 링크에 독립적으로 href.slice(0,18)+"…"를 적용하는 수준으로는 원본과 같게 만들 수 없다. URL shortener 컨텍스트의 전체 선택·예산·중복 처리 규칙은 추가 분석 대상이다. 확인하지 않은 수치 예산은 추정값을 사실처럼 쓰지 않았다.
URL이 축약되어도 identity와 원래 DOM 링크의 href는 별도다. 전체 href 조회 기능을 만들 때 표시문자열에서 원본을 복구하려 하지 말고 해당 DOM 요소를 조회해야 한다.

5-6. 범위와 부분 출력
bounds y=10000인 합성 text field도 출력됐다. 수집 경로 또한 getFullAXTree이므로 viewport-only로 볼 수 없다.
한 부모 밑에 형제700개를 둔 fixture에서는 showing 0-500 of 700 items가 나왔다. 이를 전체 트리의 총500개 제한으로 일반화하면 안 된다. Naver처럼 여러 하위 그룹을 가진 트리는 전체 출력이500개를 넘을 수 있다. 숨김·미생성·canvas 내용을 전부 읽는다는 의미도 아니다.

5-7. URL 이동과 문서
같은 tab과 같은 identity를 유지하고 tab.url만 바꾼 합성 입력은 정상 처리됐다. tab.id를 바꾸고 이전 revision을 넣으면 status5 오류였다.
실제 브라우저의 document/frame/loader 수명 관리는 JavaScript 서비스가 추가로 검사한다. URL 문자열 변화만으로 무조건 revision을 초기화하는 구현은 원본과 다르다.

6. REA가 실제로 한 일과 하지 못한 일
실제 호출:
- analyze-javascript-application: browser-service.mjs 전체 정적 분석 성공. 1,442,081바이트, AST280,915노드, parse_failures0.
- 큰 번들에 대해 지정한 semantic 노드 예산이 있었고 structural graph도 partial이어서, 이를 완전한 call graph라고 부르지 않는다.
- 원본 AST의 최상위 선언을 선택해 ax-core.mjs로 추출하고 원본 start/end/column을 focus-provenance.json에 기록했다. 집중 분석 semantic nodes5955 / relations5423, 예산 초과에 따른 omitted_nodes0이었지만 dynamic 관계는 여전히 partial이다.
- trace-application-feature의 Accessibility.getFullAXTree 문자열 seed는 no-match였다. 코드가 없다는 뜻이 아니다.
- trace-javascript-semantics의 같은 literal seed도0개. buildRevision property seed는1개였으나 traversed_relations0. 이 번들에서 REA가 자동으로 정확한 전체 실행 흐름을 복원한 것은 아니다. 실행 흐름의 근거는 원본 코드 직접 읽기와 ABI 실험이다.
- inspect-wasm-artifact는 실제 호출했으나20MB 입력이 REA의8,388,608바이트 제한을 넘어서 거절됐다. rea-wasm.json에 오류 원문을 남겼다.
- WABT wasm2wat / wasm-objdump를 직접 호출해 보완했다. REA의 제한을 몰래 수정하거나 입력을 줄여 같은 원본인 것처럼 보고하지 않았다.
- WAT 디코딩은 완료했으나 원래 Swift 소스 복구와 같지 않다. 공식 WABT 릴리스에 wasm-decompile 실행 파일은 없어 해당 시도는 실행되지 않았다. 디컴파일러로 원본 Swift 전체를 복구했다고 주장하지 않는다.

'90%/99% 똑같다'라는 수치는 제시하지 않는다. 기준 corpus와 전체 브라우저 테스트가 없어서 검증 가능한 비율이 아니다.

8. 본인 프로젝트에 적용할 구현 경계
Transport: Playwright CDPSession 또는 Chrome extension chrome.debugger를 자신의 앱과 연결한다.
Collector: getFullAXTree + DOMSnapshot + frame정보 → 정규화 snapshot.
RevisionEngine: 이전 revision + snapshot → text, identity 매핑, value-settable 정보.
ActionRegistry: identity → backendDOMNodeId/target/frame/loader 및 유효성 검사.
MCP: 브라우저·탭·에이전트 session별 revision을 분리하고 get_ax_state({tabId,disableDiffing})와 액션을 노출한다.
각 에이전트가 본 마지막 revision이 다를 수 있으므로 탭 하나에 전역 previousRevision 하나만 두면 변경분·번호 사용이 꼬일 수 있다. 이 항목은 본인 MCP 설계를 위한 제안이며 원본의 모든 multi-agent 정책을 복원한 주장이 아니다.
공통 interface 예:
  buildRevision(previous, snapshot, {mode:"auto"|"full"})
  revision.text
  revision.identityForElement(index)
  revision.isValueSettableForElement(index)

원본 모듈의 동작을 관찰 기준으로 삼고 자체 엔진을 따로 구현하면 된다. 기능 동등이 목표라면 URL 축약 정책과 표시번호 유지 정책을 명시적으로 정의할 수 있다. 원본과 문자단위 동등이 목표라면 원본 엔진/자체 엔진에 같은 fixture revision 시퀀스를 넣고 exact diff를 비교하는 후속 작업이 필요하다. 이번에 만든 하네스와 fixture가 그 비교 기준이다.

11. 검증 범위와 산출물
합성 실험 결과 항목: 231개. 파일별 {"behavior-probes.json": 16, "more-probes.json": 47, "threshold-probes.json": 37, "diff-policy-probes.json": 131}.
검증: verify-findings.mjs의23개 assertion 통과. 번호·들여쓰기·diff·1000바이트 경계·URL 축약·부분 출력·offscreen 처리 등을 검사했다. 이는23개 사이트나23개 브라우저 end-to-end 작업을 뜻하지 않는다.

핵심 파일:
- core-probe.mjs: 직접 작성한 독립 WASM ABI 하네스
- behavior-probes.mjs / more-probes.mjs / threshold-probes.mjs / diff-policy-probes.mjs: 실험 입력 생성
- verify-findings.mjs:23개 검증
- evidence/*.json: 원문 입력·출력, REA 결과, 오류, SHA-256, 검증결과
- evidence/browser-service.pretty.mjs: 포맷팅한 설치본 JavaScript
- focused/ax-core.mjs 및 evidence/focus-provenance.json: 집중분석 발췌와 원본 위치
- evidence/browser-accessibility.wat: 전체 WAT; 원본 Swift 소스가 아님
- evidence/wasm-diff-config.wat: 기본 설정값 코드
- target/: 분석한 원본의 로컬 복사본. 자체 작성 구현과 구분한다.
- tooling/, rea/: 도구 및 참고 소스. 다운로드용 ZIP에는 큰 의존성·전체 저장소를 넣지 않았다.
